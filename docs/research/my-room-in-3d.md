## 1. 研究结论

My Room in 3D 是一个基于 Three.js 的交互式 3D 个人作品集。用户通过拖拽、触摸和滚轮观察一个数字房间；屏幕、物件、灯光和动画共同传达创作者的身份与作品。

它的价值不是“用 3D 替换普通网页”，而是把个人介绍、作品和媒体入口组织成可探索的空间叙事：

```text
3D 场景（氛围与探索）
        +
语义化物件（内容入口）
        +
常规网页面板（阅读、转化与无障碍）
```

对我们而言，3D 应作为**空间化入口层**：负责第一印象和探索动机；详情内容由标准网页界面高效呈现。

## 2. 适用边界

适合：

- 个人作品集、创意开发者主页和设计工作室介绍；
- 有明确世界观、展品或故事线的品牌展示页；
- 互动展厅、活动预热页和少量高价值案例的沉浸式导览。

不适合：

- 以搜索、比较、填写表单或快速下单为主的任务；
- 首屏性能预算极紧，或低速移动网络占比很高的站点；
- 内容规模很大、需要高频更新却没有配置化内容系统的场景。

## 3. 已验证的技术链路

### 3.1 实时渲染

[入口](../../my-room-in-3d-research/src/script.js) 创建 `Experience`；[Experience](../../my-room-in-3d-research/src/Experience/Experience.js) 统一管理场景、相机、渲染器、资源、世界和导航，并在 `requestAnimationFrame` 循环中持续更新和绘制。

[Renderer](../../my-room-in-3d-research/src/Experience/Renderer.js) 使用 `THREE.WebGLRenderer` 将场景绘制到浏览器 Canvas，并把像素比限制在 1–2 之间，以控制高分屏 GPU 开销。仓库也预留了 `EffectComposer` 后处理通道，但默认没有启用。

### 3.2 资产与视觉策略

[assets.js](../../my-room-in-3d-research/src/Experience/assets.js) 列出房间、椅子、屏幕、灯具等 GLB 模型，以及烘焙光照贴图、遮罩和视频。[Resources](../../my-room-in-3d-research/src/Experience/Resources.js) 分组加载资源；[World](../../my-room-in-3d-research/src/Experience/World.js) 在资源完成后组装房间、LED、椅子、咖啡蒸汽、灯光、悬浮 Logo 和屏幕。

可提炼的性能策略：

- 使用烘焙的日间、夜间和中性贴图承担大部分光影，避免实时计算复杂全局照明；
- 将动态限制在少量对象，例如 LED、蒸汽 shader、视频屏幕和摆动 Logo；
- 使用 Draco 与 Basis 解码器，为压缩模型和纹理资源预留加载能力。

### 3.3 相机与交互手感

[Navigation](../../my-room-in-3d-research/src/Experience/Navigation.js) 维护受限的 `THREE.Spherical` 相机参数，而非直接将默认 `OrbitControls` 用作正式交互：

```text
鼠标/触摸拖拽、滚轮
        ↓
球面角度、观察目标和距离
        ↓
边界限制 + 时间平滑
        ↓
相机位置与 lookAt 更新
```

这一做法让观察范围、缩放距离和移动边界可被精确控制，避免用户穿出房间或得到破坏叙事的视角。镜头是体验引导的一部分，而不只是“可以转动的相机”。

## 4. 产品化缺口

当前项目是可观察、可缩放、含动态细节的 3D 场景，并非通用内容平台。若要承载我们的项目集合，需要补齐：

| 层次 | 需要补齐的能力 | 目的 |
| --- | --- | --- |
| 内容配置 | `项目 → 标题、摘要、封面、链接、物件标识、展示位置` 的数据清单 | 不修改场景代码即可更换内容 |
| 场景语义 | 为电脑、书架、海报、门等模型节点定义稳定业务标识 | 让模型成为可维护的内容入口 |
| 命中交互 | 用射线检测识别点击/触碰的物件，提供悬停与焦点反馈 | 将“观看场景”变成“进入内容” |
| 内容界面 | 用 HTML/React 面板或路由展示详情、外链、视频与联系信息 | 保持阅读效率、SEO 与无障碍能力 |
| 降级与性能 | 加载进度、低性能模式、减少动态效果、非 WebGL 备用入口 | 让移动设备和弱网络下仍可使用 |

## 5. 可复用架构

后续实现不应把某一间房或某一套模型硬编码为产品。建议拆分为：

```text
内容 Manifest
    ↓
场景适配层（模型节点、相机预设、触发区域）
    ↓
交互层（指针命中、键盘焦点、状态机）
    ↓
展示层（3D Canvas + HTML 内容面板）
    ↓
性能与无障碍层（加载、降级、替代导航）
```

优先建设“内容配置 + 场景入口 + 内容面板”的最小闭环；仅在叙事真正需要时再加入角色移动、物理、复杂 shader、空间音频或彩蛋。这样可保留 3D 的记忆点，而不让维护与性能成本失控。
