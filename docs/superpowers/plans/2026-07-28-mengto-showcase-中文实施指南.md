# MengTo Skills Showcase 中文实施指南

日期：2026-07-28  
用途：供项目所有者审阅整体方案、安装影响和实施进度。

## 一、中文和英文会不会影响项目

不会影响核心实现能力。

Codex 可以读取英文 `SKILL.md`，也可以用中文与用户沟通、编写产品文案和整理文档。为了兼顾可读性、技术准确性和后续更新，本项目采用下面的语言分层：

| 内容 | 使用语言 | 原因 |
| --- | --- | --- |
| README、安装说明、验证报告 | 中文为主 | 便于项目所有者审阅和维护 |
| 产品界面、教程、状态、错误 | 中文为主 | 面向中文用户直接可用 |
| 给用户的阶段总结和交付说明 | 中文 | 降低沟通成本 |
| 技术术语第一次出现 | 中文 + 英文 | 例如“固定时间步（fixed timestep）” |
| 文件名、目录名、包名 | 英文 | 与开发工具和生态保持兼容 |
| TypeScript 标识、API、测试选择器 | 英文 | 避免编码、类型和工具兼容问题 |
| PowerShell、npm、git 命令 | 英文原样 | 命令必须能够直接执行 |
| 上游 `MengTo/Skills` | 保持英文原文 | 保留来源、更新能力和差异对照 |

项目不会为了中文化而翻译或修改安装后的 `SKILL.md`。中文解释会写在项目自己的 README 和安装记录里。

目录职责：

- `apps/`：三款真正运行的产品。
- `packages/`：三款产品复用的模型、输入、类型、UI 和 Three.js 能力。
- `config/`：记录 Skill 来源、版本、用途和安装状态。
- `docs/`：中文安装说明和验证证据。

## 四、Skill 安装到哪里

项目内保留完整上游仓库：

```text
D:\codex_project_work\0728_some_github\
└── mengto-skills-showcase\skills-source\MengTo-Skills\
```

Codex 实际调用的精选 Skill 安装到：

```text
C:\Users\yun68\.codex\skills\<skill-name>\
```

两者不同：

- 项目内仓库用于固定版本、查看来源和审查更新。
- Codex 全局目录用于让 Codex 在开发任务中发现 Skill。
- 最终网页不会读取这两个目录，也不会把 Skill 打包上线。

全局安装的影响：

- 后续其他 Codex 项目也能发现这些 Skill。
- Skill 不会自动运行，只有匹配任务或明确调用时才会生效。
- 更新项目内仓库不会自动更新全局安装副本。
- 更新全局副本前必须先查看上游差异。

## 六、基础阶段做什么

基础阶段不立即制作游戏画面，先把可追踪性和复用基础建立好：

1. 创建 `mengto-skills-showcase` 工作区。
2. 将 `MengTo/Skills` 添加为固定版本的 git 子模块。
3. 记录上游仓库 URL、分支和准确提交 SHA。
4. 建立 16 个 Skill 的机器可读清单。
5. 安装缺失 Skill，不覆盖已有目录。
6. 生成中文安装说明。
7. 建立共享类型、资产注册表、输入标准化和资源释放机制。
8. 完成中文 README 和 `AGENTS.md`。

README 必须说明：

- 项目和三款产品的用途；
- 上游 Skill 源码目录；
- Codex 全局安装目录；
- 安装了哪些 Skill；
- 每个 Skill 会影响哪些产品和阶段；
- 全局安装对其他 Codex 项目的影响；
- Skill 不会进入最终产品；
- 如何检查、更新和安全移除 Skill；
- 本地上游副本与全局安装副本可能不同步。

## 七、Monster Forge｜怪物铸造所

### 产品目标

让用户像使用游戏美术审查工具一样浏览四个怪物：

- 灰烬守卫
- 琉璃爬行者
- 钟甲骑士
- 泥沼猎犬

### 可操作内容

- 从怪物目录选择资产；
- 旋转、缩放 3D 模型；
- 播放待机、行走、攻击、受击和死亡动作；
- 暂停、重新播放；
- 显示骨骼、碰撞体和装备挂点；
- 查看尺寸、动作数量、来源和生成方式。

### 中文要求

- 产品标题和说明使用中文；
- 动作按钮使用中文，内部枚举保持 `Idle`、`Walk`、`Attack`、`Hit`、`Death`；
- 错误信息说明具体失败原因；
- 来源显示为“运行时程序化（Runtime procedural）”；
- 明确提示“此资产未使用导入的 GLB/FBX 文件”。

### 完成标准

- 四张目录卡片只使用透明 PNG，不使用 Canvas；
- 选中区域只有一个实时 Three.js Canvas；
- 四个怪物都能播放五种动作；
- WebGL 失败仍能查看静态资产信息；
- 桌面、手机、键盘、触摸和减少动态效果测试通过。

## 八、Ashfall Arena｜灰烬竞技场

### 产品目标

完成一局约 8–12 分钟的动作游戏：

1. 进入训练环学习攻击和格挡；
2. 击败第一波普通敌人；
3. 选择生命或力量升级；
4. 击败精英敌人；
5. 打开 Boss 大门；
6. 击败钟鸣君主；
7. 保存完成状态。

### 游戏系统

- 移动、相机、目标锁定；
- 双武器切换；
- 连击、格挡、闪避、治疗；
- 两种普通敌人、一个精英和一个 Boss；
- 掉落、升级、存档和失败重试；
- 键鼠、触摸和标准手柄操作；
- 音效、特效、移动端和减少动态效果。

### 中文要求

- 教学目标、HUD、暂停、失败、升级和完成界面使用中文；
- 触摸控制显示“攻击、格挡、闪避、目标锁定、切换武器、治疗”；
- 音频不是唯一提示，所有关键攻击都要有可见预警；
- 验证报告用中文解释测试结果和已知限制。

### 技术原则

游戏结果由固定时间步模拟决定：

- 画面重叠不能直接造成伤害；
- 同一次攻击不能重复伤害同一目标；
- AI 每次决策可以通过相同输入重现；
- 存档只保存稳定状态，不保存动画帧或渲染器状态。

## 九、Mech Atelier｜机甲定制工坊

### 产品目标

让用户定制一台概念机甲：

- 选择游骑侦察型、堡垒运输型或神谕框架；
- 更换头部、装甲、左右武器和背部模块；
- 调整颜色、金属度、粗糙度和灯光环境；
- 查看重量、战力、防护、机动性和概念价格；
- 使用分解视图和部件热点；
- 保存配置、复制分享链接、导出产品海报。

### 中文要求

- 选项、兼容性提示、错误和摘要使用中文；
- 价格单位显示“信用点”；
- 页面明确显示“概念配置，不提供结算或库存功能”；
- WebGL 失败后仍能修改配置、查看摘要和复制链接。

### 完成标准

- 三种底盘与所有部件遵守准确兼容规则；
- 非法链接会恢复到合法配置并用中文说明；
- 分享链接和本地保存可以往返恢复；
- 可以导出 1600×1200 PNG 海报；
- 手机、键盘、触摸和减少动态效果测试通过；
- 页面没有支付、库存、账号或订单功能。

## 十、建议实施顺序

```text
基础目录与 Skill 安装
        ↓
共享资产和 Three.js 生命周期
        ↓
Monster Forge
验证模型、动作、挂点和透明预览
        ↓
Ashfall Arena
把资产投入真实战斗和完整游戏循环
        ↓
Mech Atelier
把共享 3D 能力转化为商业配置产品
        ↓
全套移动端、无障碍、性能和发布验证
```

原因：

- 先做资产工具，可以尽早发现模型、动作和资源释放问题。
- 游戏使用已经验证的资产，减少战斗阶段返工。
- 商业配置器复用稳定的 3D 管线，同时证明技术不局限于游戏。

## 十一、实施过程中如何汇报

每个阶段向用户提供中文报告：

1. 本阶段使用了哪些 Skill。
2. 修改了哪些产品能力。
3. 新增或变更了哪些目录。
4. 测试和构建是否通过。
5. 浏览器实际验证了哪些状态。
6. 当前有哪些已知限制。
7. 下一阶段准备做什么。

错误输出可以保留英文原文，但必须补充中文解释和影响范围。

## 十二、常用技术词对照

| 英文 | 中文解释 |
| --- | --- |
| Skill | 给 Codex 使用的开发操作规程 |
| runtime | 产品真正运行时 |
| procedural | 由代码程序化生成 |
| provenance | 资产来源与生成方式 |
| fixed timestep | 固定时间步模拟 |
| collider | 碰撞体 |
| socket | 装备或部件挂点 |
| deterministic | 相同输入可以得到相同结果 |
| fallback | 功能失败时的可用降级界面 |
| reduced motion | 减少动态效果的无障碍偏好 |
| fixture | 用于测试特定状态的固定数据 |
| vertical slice | 可以完整试玩的一小段产品 |
| submodule | 固定另一个 git 仓库版本的引用 |
| bundle | 构建后交付给浏览器的代码资源 |

## 十三、用户审阅重点

用户不需要逐行阅读英文代码计划，主要确认：

- 产品方向是否仍符合预期；
- 安装目录是否清楚；
- 全局安装影响是否可以接受；
- Skill 清单是否合理；
- 三款产品的首版范围是否需要增减；
- 中文产品文案和说明是否足够清晰；
- 每个阶段的验证证据是否满足交付要求。

代码级接口、测试步骤和命令由 Codex 按四份详细计划执行。
