## 目标

将 `r3f-scroll-rig` 研究正式登记为根仓库的第 08 个子项目，并复用仓库已有的“原项目效果 → 我们的应用效果”展示模式，同时呈现：

1. 库自身样例证明的基础能力；
2. 我们制作的《雾屿灯塔》样例证明的实际应用能力。

Finesse Skill 产品研究由第 08 项顺延为第 09 项，内容与研究结论不删除。

## 已确认的展示原则

- 不新增独立对照展厅。
- 不在同一页面同时运行两套 WebGL。
- 不重新设计仓库已经具备的展示结构。
- 复用第 05 项 Fungarium 的组织方式：根 README 中先展示原项目证据，再展示本仓库应用证据，最后给出来源、边界和运行入口。
- 动图、截图和说明承担“快速理解”职责；完整灯塔交互仍在独立、可运行的项目目录中完成。

## 项目归属与目录

根仓库新增一个可独立复现的项目目录：

`r3f-scroll-rig-showcase/`

该目录以已经完成的 `examples/lighthouse-scroll-rig-demo` 为基础，包含灯塔样例的源代码、锁文件、素材、测试和 README。它通过固定的 npm 依赖使用 `@14islands/r3f-scroll-rig`，而不是把整个上游仓库复制进根仓库。

现有本地目录的定位如下：

- `r3f-scroll-rig-research/`：研究和开发工作仓库，包含上游源码及本地提交；其当前提交不存在于上游远端，因此不能作为可克隆的 Git 子模块登记。
- `r3f-scroll-rig-legacy-demo/`：原库样例的本地观察来源。
- `r3f-scroll-rig-showcase/`：根仓库正式跟踪、面向读者运行的第 08 子项目。

这样可以避免不可复现的嵌套 Git 仓库，也避免把上游完整源码重复提交到笔记仓库。

### 第 08 项正文

第一段解释研究问题：`r3f-scroll-rig` 如何让语义化 DOM、滚动进度和共享 WebGL 画布保持同步。

随后展示两组证据：

1. **原库样例效果**
   - 使用 `docs/demos/08-r3f-scroll-rig-original.gif`。
   - 说明它证明的能力：DOM/WebGL 尺寸对齐、滚动跟踪、粘性场景、平滑滚动协作与共享 Canvas。
   - 采集来源固定为本地历史样例快照 `r3f-scroll-rig-legacy-demo/`，上游提交为 `adf7d47`；仓库元数据版本为 `7.0.7`。
   - 在交付记录中读取锁文件或安装树，写明该历史样例实际解析的库版本，不假定它与我们的 `8.15.0` 相同。
   - 标明上游仓库、固定提交、ISC 许可和非官方关联边界。

2. **我们的《雾屿灯塔》样例**
   - 使用 `docs/demos/08-r3f-scroll-rig-lighthouse.gif`。
   - 说明它证明的能力：2.5D 分层叙事、稳定构图、连续接近、信号事件、航线状态、减少动态效果和无 WebGL 回退。
   - 明确它不是把单张灯塔图片自动转换成真实 3D 模型。

两组证据后增加一句结论：

> 原库样例回答“这个封装库能做什么”，灯塔样例回答“我们如何把它用于一个真实的滚动视觉场景”。

## 验收标准

1. 根 README 的项目表中，r3f-scroll-rig 为第 08 项，Finesse 为第 09 项。
2. 第 08 项正文同时展示原库动图和灯塔动图，并准确说明两者分别证明什么。
3. `r3f-scroll-rig-showcase/` 可以从根仓库独立安装、启动、测试和构建。
4. 灯塔样例继续通过现有完整测试集，并保留稳定构图、原始漂移、减少动态效果和静态回退入口。
5. 原库来源、固定版本、许可和非官方关联边界清晰。
6. 根 README 和第 08 项 README 的所有本地链接有效。
7. 不提交 `node_modules`、`dist`、临时录制文件、本地研究仓库的 `.git` 数据或不可复现的 gitlink。

## 风险与处理

- **上游样例不可用**：以已固定来源的本地样例重新采集；README 保留来源和固定版本。
- **两套样例版本不同**：原库历史样例和灯塔样例分别记录实际版本；对照只用于解释能力演进，不声称两者是同版本性能基准。
- **嵌套仓库不可复现**：根仓库只跟踪独立 showcase 目录，不直接登记本地研究仓库。
- **两段动图体积过大**：控制视口、帧率、时长和色彩数量，在可读性不下降的前提下压缩。
- **能力描述夸大**：所有文案必须能由原库入口、灯塔入口、自动测试或浏览器观察直接证明。
- **编号链接遗漏**：同时检查目录表、正文标题、本地运行和相关文档四个位置。
