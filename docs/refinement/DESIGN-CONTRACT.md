# 设计契约：雾屿灯塔

## 基本信息

| 字段 | 约定 |
| --- | --- |
| Entry mode | Brief-led |
| Request revision | 0 |
| Target user and context | 偏好编辑式旅行叙事、摄影与沉浸式网页体验的中文读者，在桌面或移动浏览器中探索虚构岛屿。 |
| Desired first impression | 从近岸礁石之间望见暮蓝海面与唯一暖光灯塔；画面安静、精致、有方向感。 |
| Visual ambition | Immersive |
| Experience architecture | Spatial Stage |
| Scene base | CSS 驱动的 2.5D 图像分层；原生 DOM 为可读和可访问界面。 |
| Scene persistence | 普通动态模式下，场景在完整时间轴中保持可见；最终航线档案浮于同一场景。减少动态模式下允许场景让位给线性内容。 |
| Foreground control model | 持久页头导航、两个叙事面板、航线档案的前后按钮、拖拽、键盘与展开说明。 |
| State-to-scene mapping | 开场为完整主视觉；故事 A 与故事 B 分别改变焦点与文字；最终状态显现航线档案并维持可操作；图片失败保留深蓝降级世界。 |
| Mobile transformation | 缩短时间轴、停用指针视差、收窄文案并将航线卡片保持为可触达的底部前景层。 |
| Fallback | 无图片时保留语义内容和深色底图；减少动态模式中使用静态主视觉与线性内容。 |

## 约束

- 视觉锚点是略偏右的灯塔与唯一琥珀暖光；左、右礁石只作框景，不能遮挡移动端主体。
- 中文为主，英文仅用于品牌名、章节编号与方向标签；所有可见文本保留在 HTML 中。
- 只使用原生 HTML、CSS、JavaScript、Vite、Vitest 与 Playwright；不加入运行时动画库或 3D 框架。
- 时间轴的所有画面状态从局部滚动进度 `p` 决定，必须可逆。
- 页面不锁定原生纵向滚动，不产生横向页面溢出。
- 首屏图片完成解码后才显现组合舞台；后段航线图片懒加载。
- 所有可见控件都可通过键盘抵达并具有可见焦点。

## 信息与操作边界

主旅程：读者从首屏向下滚动，阅读两个叙事节点，进入航线档案，用按钮、拖拽、触摸或键盘浏览并展开四条航线。

用户定义阶段：

1. 创建原创分层灯塔场景。
2. 建立电影式滚动叙事。
3. 交付可操作航线档案。
4. 验收桌面、平板、手机、键盘、减少动态和控制台错误。

所需交付：可运行源码、README、素材清单、时间轴地图、缺失素材说明、验证报告和少量最终浏览器证据。

## 授权与完成条件

Autonomy authorization：用户明确授权“你来定”、接受原创分层图像素材、确认设计和实施计划，并选择当前会话直接执行。常规设计、实现、测试、浏览器验证与文档决策无需再次确认。

User-decision boundary：只有使用需要外部 API 密钥的真原生透明图像生成路径、真实外部服务、身份验证或明显扩大为多页产品时才需要新增授权。

Observable completion criteria：首屏有完整编辑式构图；八个时间轴检查点无画布边缘、碰撞或突变；反向滚动可逆；航线档案的按钮、拖拽、触摸和键盘可用；五个视口、200% 放大、减少动态、图片失败降级和控制台都获得真实浏览器证据；所有交付文档存在且与证据一致。
