# 统一产品能力展厅与中文新手引导设计

日期：2026-07-29

状态：已完成对话设计确认，等待书面规格确认

目标受众：非技术客户、管理者与第一次访问者

## 1. 背景与问题

现有套件已经包含三款可运行产品，但用户进入任意产品后，无法快速回答：

1. 这个模块是什么；
2. 应该如何体验；
3. 它适用于什么业务；
4. 三个模块为什么同时存在；
5. Skill 与最终产品是什么关系。

根因不是产品功能不足，而是缺少统一入口、参观路线、产品内任务说明、Skill 到产品的映射，以及返回展厅的导航。

本次改动不增加第四款产品，也不重做三款产品的核心体验。它新增一个中文优先的能力展厅，并为三款产品补齐一致的新手引导。

## 2. 已确认的产品方向

采用“产品能力展厅”方案：

- 第一屏直接解释这不是一款包含三个关卡的游戏，而是三款互补产品；
- 三张产品卡固定回答作用、体验方式、Skill 能力和商业场景；
- 用户可以先看说明，也可以直接进入体验；
- 产品第一次打开时显示中文任务引导；
- 每个产品始终可以重新打开说明并返回展厅；
- 首页用一句故事线串联三款产品：“同一套专业 Skill，如何产出三种完全不同的可运行产品。”

未采用的方向：

- 纯故事化长页：叙事更强，但查找单个产品较慢；
- 开发者控制台：技术信息充分，但第一次访问者负担过高。

## 3. 设计契约

```text
Entry mode: Revision-led
Request revision: 1
Target user and context: 非技术客户、管理者与第一次访问者；不了解 Three.js、Skill 或当前目录结构
Desired first impression: 这是一个可信、可体验、易理解的三产品能力展，而不是三个缺乏关联的技术 Demo
Visual ambition: Editorial
Experience architecture: Editorial Flow（展厅）+ 保留现有产品的 Spatial Stage / Hybrid Workspace
Visual constraints: 中文优先；暗色专业基调；真实产品截图；高对比正文；三产品使用独立强调色；不依赖 WebGL 才能理解
Information constraints: 第一屏只解释套件定位；每张卡固定回答五类问题；测试细节默认折叠；不以英文 Skill 名称作为主叙事
Operation constraints: 一条命令启动四个应用；产品支持返回展厅、重新打开说明、键盘关闭与焦点返回；移动端提供触摸说明
State constraints: 首访引导、已关闭引导、重新打开、选择“不再自动显示”、存储不可用、WebGL 不可用、reduced-motion
Environment constraints: Node.js 22.12+；Vite；现有 Three.js 产品；本地端口 4172–4175；不引入后端
Primary journey: 进入展厅 → 30 秒理解三产品 → 选择产品 → 阅读中文任务 → 完成核心体验 → 返回展厅
User-defined phases: 统一展厅；产品内引导；一条命令运行；跨表面验收与文档
Required artifacts: 展厅应用、共享引导模块、三个产品集成、统一启动脚本、README、自动测试、最终浏览器证据
Autonomy authorization: 用户先后确认目标受众、产品能力展厅方案、首页结构、三产品引导、视觉技术结构和验收标准，并要求继续
User-decision boundary: 公开部署、真实分析埋点、后端、认证、第四款产品、真实商业交易流程
Observable completion criteria: 用户无需阅读开发 README 即可说明三产品作用、进入并完成对应首个任务、重新查看说明并返回展厅
Coverage record: 见第 10 节
```

## 4. 信息架构

### 4.1 展厅首页

页面按以下顺序组织：

1. **首屏定位**
   - 主标题：“一套专业 Skill，三种可运行产品”
   - 副标题明确：这不是同一款游戏的三个关卡。
   - 主操作：“开始参观”
   - 次操作：“Skill 如何工作”

2. **三款产品卡**
   - 产品名称与一句话定位；
   - “它是什么”；
   - “你可以体验什么”；
   - “证明的能力”；
   - “可以改造成什么产品”；
   - 预计体验时间；
   - “先看说明”与“进入体验”。

3. **Skill 如何产生产品**
   - 使用四步语义流程：
     `选择业务目标 → Codex 调用相关 Skill → 开发与测试 → 交付普通网页产品`
   - 明确 Skill 不会被浏览器加载，也不是运行时插件。

4. **业务选择指南**
   - 管理和验收 3D 资产 → Monster Forge；
   - 制作可玩的互动内容 → Ashfall Arena；
   - 展示和配置复杂商品 → Mech Atelier。

5. **验证与边界**
   - 默认展示非技术结论；
   - 技术测试数量、GPU、设备和真人门槛放入可展开详情；
   - 不把自动测试写成真人可用性证明。

### 4.2 产品说明预览

“先看说明”打开语义化对话框，不离开展厅。内容包括：

- 产品作用；
- 三步体验任务；
- 典型商业场景；
- 主要 Skill 能力组；
- 预计体验时间；
- “进入体验”与“关闭”。

Escape 关闭，关闭后焦点返回原按钮。

## 5. 三产品新手引导

### 5.1 Monster Forge

**作用：** 检查和管理 3D 怪物资产。

**任务：**

1. 选择一个怪物；
2. 切换动作、骨骼或碰撞体；
3. 查看模型来源与技术参数。

**意义：** 减少游戏资产验收、沟通和返工成本。

### 5.2 Ashfall Arena

**作用：** 展示完整动作游戏系统。

**任务：**

1. 学会移动、攻击、闪避和格挡；
2. 完成普通敌人与精英战；
3. 选择升级并挑战 Boss。

**意义：** 快速验证战斗手感、AI、关卡和移动端体验。

**特殊约束：** 欢迎面板打开期间不推进战斗模拟，不接收战斗输入；用户点击“开始体验”后才恢复或开始游戏。

### 5.3 Mech Atelier

**作用：** 配置和展示复杂 3D 商品。

**任务：**

1. 更换机体、装甲和武器；
2. 查看负载、火力、防御和兼容性变化；
3. 使用拆解视图、分享配置或导出海报。

**意义：** 可迁移到汽车、工业设备、家具和定制商品销售。

### 5.4 统一引导行为

三个产品统一提供：

- 首次访问自动显示中文引导；
- “这是什么？”按钮可重新打开；
- “返回能力展厅”链接；
- “不再自动显示”选项；
- 存储不可用时仍可正常打开、关闭和重新查看；
- 桌面键鼠与移动触摸说明；
- 可见焦点、Escape 关闭和焦点返回；
- reduced-motion 下取消非必要入场动画。

引导不得遮蔽永久恢复路径；即使用户选择不再自动显示，“这是什么？”按钮仍保留。

## 6. 视觉方向

### 6.1 总体风格

- 保留现有暗色、专业、沉浸式产品气质；
- 展厅背景和正文亮度高于三款产品，优先解决深色小字可读性；
- 不用 emoji、CSS 伪图、占位框或手工 SVG 冒充产品资产；
- 使用三款产品的真实验收截图作为产品卡主视觉；
- 首页核心意义不依赖截图、Canvas 或 WebGL 才能读取。

### 6.2 产品识别

| 产品 | 强调色 | 视觉含义 |
| --- | --- | --- |
| Monster Forge | 暖橙 | 资产、锻造、检查 |
| Ashfall Arena | 灰烬红 | 战斗、风险、反馈 |
| Mech Atelier | 冷青 | 精密、配置、工业 |

颜色不作为唯一识别方式，产品名称、图像替代文本和文字标签必须同时存在。

### 6.3 响应式

- 桌面：三张卡并列，首屏可见定位和开始参观入口；
- 平板：两列或单列，产品说明对话框不超出视口；
- 390px 手机：单列卡片，按钮保持可触达，说明使用底部面板或全宽对话框；
- 现有产品的空间场景和移动面板结构保持不变，引导作为前景层接入。

### 6.4 动效

- 只用轻量进入、展开和焦点反馈解释状态变化；
- 不使用持续漂浮或装饰性视差；
- `prefers-reduced-motion: reduce` 时立即切换状态，不使用位移动画。

## 7. 技术结构

### 7.1 新增展厅应用

新增工作区：

```text
apps/showcase-hub
```

职责：

- 渲染展厅首页；
- 维护三产品说明内容与业务映射；
- 打开产品说明对话框；
- 根据环境解析三产品 URL；
- 不导入 Three.js，不依赖 WebGL。

默认开发端口：`4172`。

### 7.2 共享引导包

新增工作区：

```text
packages/showcase-guide
```

建议公开接口：

```ts
type ProductGuideConfig = {
  productId: "monster-forge" | "ashfall-arena" | "mech-atelier";
  title: string;
  purpose: string;
  steps: readonly string[];
  meaning: string;
  desktopControls: readonly string[];
  touchControls: readonly string[];
  hubHref: string;
  onOpen?: () => void;
  onClose?: () => void;
};

type ProductGuideController = {
  open(): void;
  close(): void;
  destroy(): void;
  isOpen(): boolean;
};

function createProductGuide(
  host: HTMLElement,
  config: ProductGuideConfig,
): ProductGuideController;
```

模块职责：

- 创建语义化说明对话框和持久入口；
- 安全读取和写入“不再自动显示”偏好；
- 在 `localStorage` getter、读取或写入失败时退化为当前会话行为；
- 管理焦点、Escape、背景交互和销毁；
- 暴露 `onOpen` / `onClose`，由 Ashfall 控制暂停边界；
- 提供共享样式，但通过语义变量允许三个产品继承自身强调色。

它不管理游戏状态、商品配置、Three.js 场景或产品路由。

### 7.3 产品 URL

开发默认值：

| 产品 | URL |
| --- | --- |
| 展厅 | `http://127.0.0.1:4172/` |
| Monster Forge | `http://127.0.0.1:4173/` |
| Ashfall Arena | `http://127.0.0.1:4174/` |
| Mech Atelier | `http://127.0.0.1:4175/` |

展厅支持 Vite 环境变量覆盖产品地址；共享引导支持环境变量覆盖展厅地址。未配置时使用上述本地默认值。未来部署可以改为同域子路径，但本次不实现部署系统。

### 7.4 一条命令运行

新增：

```text
scripts/dev-showcase.mjs
```

根脚本：

```json
"dev": "node scripts/dev-showcase.mjs",
"dev:hub": "npm run dev --workspace @showcase/hub"
```

`npm run dev` 顺序启动四个 Vite 子进程，转发退出信号，并在任一必需服务启动失败时清理其余子进程。终端输出只显示产品名称和可点击地址。

现有 `dev:forge`、`dev:arena`、`dev:atelier` 保留。

## 8. 资产策略

使用现有真实验收截图，选取并复制为展厅的有意产品资产：

- Monster Forge：目录或检查态；
- Ashfall Arena：战斗起始态；
- Mech Atelier：配置或总结态。

最终资产放入：

```text
apps/showcase-hub/public/previews
```

临时浏览器截图继续保存在忽略目录，不提交调试迭代图。提交的三张预览图需要有明确文件名、替代文本和来源说明。

## 9. 错误与回退

- 展厅本身不使用 WebGL；图片加载失败时，卡片文字和操作仍完整；
- 产品链接使用正常锚点，不引入客户端路由依赖；
- 说明存储失败不阻止引导使用，只是不记住“不再自动显示”；
- 产品 URL 配置缺失时使用本地默认值；
- 统一启动脚本遇到端口占用时明确指出产品和端口，不静默改用未知端口；
- Ashfall 引导打开期间以现有暂停机制或显式引导门禁停止模拟，不使用只遮罩画面的伪暂停；
- 关闭或销毁引导后清理事件监听器，并恢复触发按钮焦点。

## 11. 测试策略

### 11.1 单元与契约

- 产品内容模型包含名称、作用、任务、能力、商业场景、时间与 URL；
- 共享引导的首访、关闭、重新打开和安全存储；
- Escape、焦点返回和销毁；
- Ashfall 的引导门禁不会推进模拟；
- 启动脚本的固定端口、失败清理和终端输出；
- README 包含非技术定位与一条命令启动。

所有新行为遵循测试先行：先看到缺少功能导致的明确失败，再写最小实现。

### 11.2 浏览器

- 展厅桌面主旅程；
- 390px 手机主旅程；
- 产品说明对话框；
- 键盘焦点顺序与 Escape；
- reduced-motion；
- 三产品首访、重新打开和返回展厅；
- Ashfall 引导期间零战斗推进；
- 存储不可用；
- 现有三产品核心浏览器回归。

## 12. 非目标

本次不包含：

- 新增第四款产品；
- 重做三款产品的核心玩法或配置系统；
- 后端、登录、账号、云存档或分析埋点；
- 公开部署与 CDN；
- 真实交易、库存、订单、支付或履约；
- 新的 WebGL 展厅场景；
- 明暗主题切换；本次明确支持高对比暗色主题；
- 用自动化替代 Ashfall 的 8–12 分钟真人首次体验门槛。

## 13. 完成定义

只有以下条件同时满足才可以交付：

1. 非技术访客能从展厅第一屏理解三产品关系；
2. 三产品卡完整回答作用、体验、能力、场景和时间；
3. 三款产品首访引导、重开和返回路径均可用；
4. Ashfall 在说明打开时不会隐形推进；
5. 一条命令可以稳定启动固定四端口；
6. 桌面、390px 手机、键盘和 reduced-motion 证据完整；
7. README 与实际启动方式一致；
8. 自动测试、构建、浏览器回归和差异检查通过；
9. 覆盖矩阵中没有 `continue`；
10. 外部设备、公开部署和真人门槛保持如实开放。
