# 雾村原创动态背景音乐设计

**日期：** 2026-07-29

**状态：** 已完成音乐方向与播放架构确认，等待书面规格复核

**适用项目：** `rural-mutation-escape`

## 背景

当前项目没有 MP3、OGG 或 WAV 音乐资源。`src/audio-feedback.js` 只通过
Web Audio 振荡器播放任务提示、章节完成和弦、进入危险提示和心跳。这些声音
能够反馈事件，但不能形成持续的场景氛围、叙事节奏或追逐压力，因此不能视为
真正的背景音乐。

本设计增加原创、可追溯、可无缝循环的本地音乐资产。音乐采用同步双层结构：
探索层与危险层长度、节拍和循环点完全一致，运行时始终保持同一播放相位，只
根据危险状态调整增益。现有提示音和心跳保留为音效层。

## 目标

- 为农村黄昏、居民躲藏和异变爆发建立连续的原创音乐氛围。
- 使用真实的本地音频文件，而不是把运行时振荡器提示音扩充为伪背景音乐。
- 让探索、追逐、近身威胁、脱险和章节完成具有连续且可读的音乐变化。
- 保证两个循环层采样级同步，状态变化不重新开始音乐。
- 复用现有首次交互解锁、静音、页面后台暂停和危险快照。
- 在音乐加载、解码、播放或恢复失败时安全降级，不阻塞游戏与视觉反馈。
- 保存生成脚本、母带、编码版本、参数和哈希，使原创来源可以复核。
- 不增加运行时 npm 依赖。

## 非目标

- 本轮不加入空间化环境声、角色语音、广播对白或脚步声库。
- 本轮不制作多章节完整原声带，也不为四个任务分别制作独立曲目。
- 本轮不加入音乐与音效的独立可见音量滑杆；内部保留独立总线，界面继续使用
  一个总静音按钮。
- 本轮不导入外部“免版税”音乐、受保护游戏音乐或模仿具体艺术家的作品。
- 本轮不修改追逐、战斗、失败、移动端操控或故事判定。

## 方案选择

### 未采用：单轨完整混音

单个 48 秒循环最容易集成，资源与解码内存最少，但追逐状态只能整体升降音量，
无法在保持主题连续的同时增加危险细节。

### 采用：同步双层配乐

探索层与危险层均为 48.000 秒、60 BPM、4/4 拍。两层在同一个
`AudioContext` 时间点开始并循环，通过独立 `GainNode` 平滑改变存在感。
这在听感、动态性、资源规模和维护成本之间最平衡。

### 未采用：分任务阶段配乐

每个故事目标使用不同曲目可以增加叙事变化，但会扩大资源、过渡和测试范围，
也会增加短流程中的切换频率，不符合本轮聚焦背景音乐基础设施的目标。

## 音乐内容

### `rural-dusk-bed`

- 时长：48.000 秒。
- 规格：48 kHz、立体声 WAV 母带。
- 结构：12 小节、60 BPM、4/4 拍。
- 内容：缓慢低频弦乐质感、过滤风声、稀疏木质敲击、轻微虫鸣质感和克制的
  三音动机。
- 听感：黄昏、潮湿、空旷、有生活痕迹但逐渐不安。
- 旋律保持稀疏，不能覆盖任务提示、心跳或未来对白。

### `mutation-danger-layer`

- 时长、采样率、声道数、节拍与探索层完全一致。
- 内容：低频脉冲、摩擦噪声、不稳定音程、偏移的木质冲击和克制的高频张力。
- 单独播放时保持稀疏；与探索层叠加后形成追逐压力。
- 不包含前奏、尾奏或会暴露循环点的长衰减尾音。

### `mutation-reveal-stinger`

- 时长：3.000 秒。
- 在故事目标首次切换到 `escape_south_gate` 时播放一次。
- 内容：短促低频冲击、向下弯曲的异变音色和快速消散的摩擦尾音。
- 不能在每次进入追逐时重复播放。

### `south-gate-escape-stinger`

- 时长：6.000 秒。
- 在 `chapter-completed` 事件发生时播放一次。
- 内容：保留三音动机，但从不稳定音程收束到开放音程。
- 播放时两个循环层在约 5 秒内淡出。

## 原创生成与资产来源

音乐由仓库内的确定性离线脚本生成。脚本使用固定随机种子、加法与调频合成、
有色噪声、包络、谐振器和滤波器生成弦乐、风声、木质敲击和摩擦质感。脚本
输出完整 WAV 母带，FFmpeg 只负责响度处理、编码和技术检查，不承担作曲。

建议文件结构：

```text
rural-mutation-escape/
├─ scripts/
│  ├─ render-rural-score.mjs
│  └─ encode-rural-score.mjs
├─ audio-source/
│  ├─ manifest.json
│  └─ masters/
│     ├─ rural-dusk-bed.wav
│     ├─ mutation-danger-layer.wav
│     ├─ mutation-reveal-stinger.wav
│     └─ south-gate-escape-stinger.wav
└─ src/assets/audio/
   ├─ rural-dusk-bed.ogg
   ├─ rural-dusk-bed.mp3
   ├─ mutation-danger-layer.ogg
   ├─ mutation-danger-layer.mp3
   ├─ mutation-reveal-stinger.ogg
   ├─ mutation-reveal-stinger.mp3
   ├─ south-gate-escape-stinger.ogg
   └─ south-gate-escape-stinger.mp3
```

`audio-source/manifest.json` 为每个资产保存：

- 稳定资产 ID、生成脚本版本和固定随机种子。
- 采样率、声道数、精确时长、BPM 和循环边界。
- WAV、OGG、MP3 的 SHA-256。
- 响度、峰值和循环接缝检测结果。
- 来源声明 `original procedural composition for rural-mutation-escape`。
- 禁止模仿具体艺术家或受保护作品的说明。

WAV 母带保留在仓库中，但不被 Vite 运行时导入。OGG 和 MP3 被提交为运行时
资产，普通构建不依赖本机安装 FFmpeg。

## 音频架构

```text
AudioContext
└─ masterGain
   ├─ musicGain
   │  ├─ explorationGain → rural-dusk-bed
   │  └─ dangerGain → mutation-danger-layer
   └─ sfxGain
      ├─ 任务、章节提示和心跳
      └─ reveal / escape stinger
```

### 模块边界

- `src/audio-feedback.js`
  - 保持当前 `createAudioFeedback()` 公共入口。
  - 负责 `AudioContext`、主总线、音效总线、提示音、心跳、总静音和生命周期。
  - 将连续音乐控制委托给音乐模块。
- `src/music-director.js`
  - 负责音乐资源加载、解码、同步循环、故事 stinger 和音乐状态淡变。
  - 不读取 DOM，不判断游戏逻辑，只消费故事事件与危险快照。
- `src/main.js`
  - 注入音乐 URL。
  - 在真实用户手势中调用解锁。
  - 将故事事件和危险快照转发给音频外观对象。
  - 在页面卸载时调用 `dispose()`。
- `src/ui.js` 与 `index.html`
  - 保留单一声音按钮。
  - 展示锁定、加载、播放、静音和不可用状态。

### 资源选择

音乐模块按资产组尝试 OGG，解码失败时改用 MP3。一个会话只保留成功格式的
解码结果，不能同时解码两套格式。两个 48 秒立体声循环和两个短 stinger 的
总解码内存目标不超过 42 MB。

### 同步循环

探索与危险循环使用两个 `AudioBufferSourceNode`。资源全部解码后，在同一个
`context.currentTime + leadTime` 启动，设置相同的 `loopStart = 0` 和
`loopEnd = 48`。状态更新只改变 `explorationGain` 与 `dangerGain`，不能停止、
重建或重新定位循环源。

页面后台暂停使用 `AudioContext.suspend()`，因此循环相位会冻结。返回前台后
恢复同一上下文，不重新创建音乐源。

## 状态映射

音乐只使用生产故事事件与危险快照。`birth`、`contact` 等证据 URL 参数不是
生产音乐状态来源。

| 状态 | 探索层 | 危险层 | 过渡 |
|---|---:|---:|---|
| `safe` | 基准音量 | 静音 | 初次启动淡入约 2 秒 |
| `chase` | 降低约 2 dB | 随 `danger.intensity` 增至中高 | 淡入约 2 秒 |
| `threaten` | 降低约 3 dB | 高强度 | 约 0.8 秒达到目标 |
| `recover` | 逐步恢复 | 逐步退出 | 固定约 4 秒，不跟随 1.2 秒 UI 突然截断 |
| `complete` | 淡出 | 淡出 | 约 5 秒，同时播放逃生 stinger |

相同模式与近似强度的连续帧不能重复安排增益曲线。强度只有跨过有意义阈值时
才更新目标，避免每帧取消和重建自动化事件。

`mutation-reveal-stinger` 由故事从 `reach_granary` 进入
`escape_south_gate` 的一次性事件驱动。`south-gate-escape-stinger` 只由
`chapter-completed` 驱动。

## 首次解锁与播放

- 页面加载后可以预取压缩文件，但不能自动播放。
- 首次键盘按键、画布按下或声音按钮点击，都在同一次可信用户手势内执行：
  1. 创建或恢复 `AudioContext`。
  2. 解码已经预取的候选资源。
  3. 创建并同步启动循环源。
  4. 根据当前故事与危险状态设置目标增益。
- 重复解锁是幂等操作，不能重复创建上下文、解码缓存或音乐源。
- 如果解码尚未完成，按钮显示加载状态；完成后在仍允许播放的情况下启动。
- 取消静音操作同时尝试 `unlock()` 和 `resume()`，修复“后台静音后取消静音仍
  无声”的路径。

## 静音、后台与持久化

- 内部保留 `musicGain` 与 `sfxGain`，界面第一版只控制 `masterGain`。
- 静音使用存储键 `rural-escape.audio-muted.v1`。
- 初始按钮状态区分：
  - `locked`：点击开启声音。
  - `loading`：正在加载声音。
  - `playing`：关闭声音。
  - `muted`：开启声音。
  - `error`：背景音乐不可用，视觉反馈仍可用。
- 切到后台时：
  - 暂停 `AudioContext`。
  - 停止并清理尚未结束的一次性提示音与 stinger。
  - 保留循环源与循环相位。
- 返回前台时按当前静音、故事和危险状态恢复，不补播后台期间错过的提示音。

## 声音节点与资源生命周期

- 所有一次性音效加入活动 voice 注册表并设置并发上限。
- `onended` 必须断开振荡器、BufferSource 与 voice GainNode。
- 新 stinger 可以按优先级停止同类旧 stinger，任务提示不能无限叠加。
- `dispose()` 停止全部循环与 voice、清空注册表、断开所有总线、释放媒体缓存
  引用并关闭 `AudioContext`。
- 页面卸载和开发环境热更新都必须调用 `dispose()`。

## UI 与可访问性

- 右下角按钮的可见图标保持简洁，但 ARIA 文案从“音效”改为“声音”。
- 按钮点击本身是合法解锁手势。
- 音乐不可用不隐藏视觉危险提示、任务完成提示和字幕。
- 静音状态重新加载后保持。
- 本轮不让 `prefers-reduced-motion` 自动静音；声音控制由玩家明确决定。
- 调试句柄只读暴露：
  - `contextState`
  - `assetState`
  - `musicState`
  - `dangerMix`
  - `activeVoices`
  - `muted`

## 错误处理

- 网络、文件、解码或节点创建失败时，按 OGG → MP3 → 音乐关闭顺序降级。
- 音乐关闭后，现有提示音和心跳在可用时继续工作。
- AudioContext 不可用时，全部音频安全关闭，游戏和视觉反馈继续。
- `play`、`resume` 或解码失败可以在下一次真实用户手势中重试。
- 同一种错误每个会话最多记录一次，不能在帧循环中刷屏。
- 资产状态错误不改变故事、追逐、碰撞或 UI 任务状态。

## 技术质量标准

- 循环资产精确为 48.000 秒，探索层和危险层样本数相同。
- 编码前后都检查声道数、采样率、时长和 SHA-256。
- 母带综合响度目标：
  - 探索层约 `-22 LUFS`。
  - 危险层单独约 `-25 LUFS`。
  - stinger 约 `-18 LUFS`。
- 任意运行时组合的真峰值不超过 `-1 dBTP`。
- 循环边界使用渲染阶段交叉处理，首尾不得出现可听点击、直流突变或明显尾音截断。
- 运行时不得在每帧创建音频节点、发起资源请求或重新开始循环。
- 音频资产目标发布体积为 OGG 与 MP3 合计不超过 4 MB。

## 测试设计

### 音频资产检查

- 生成脚本使用固定种子时输出稳定的 PCM 哈希。
- 两个循环样本数、采样率、声道数和时长完全相同。
- 检查峰值、响度、静音文件、非有限样本和循环首尾差异。
- 编码文件存在且 manifest 哈希与实际文件一致。

### 单元测试

通过注入 `AudioContextCtor`、资源读取函数和存储对象验证：

- 无 AudioContext 时安全降级。
- 重复 `unlock()` 只创建一套总线和一对循环源。
- OGG 解码失败时只尝试一次 MP3 回退。
- 两个循环使用相同开始时间和循环边界。
- 相同危险快照不重新启动音乐或重复安排增益。
- `safe / chase / threaten / recover / complete` 映射到正确增益与过渡时间。
- reveal 与 escape stinger 每个故事事件只播放一次。
- 静音、后台、前台、取消静音路径能够恢复。
- 加载和解码失败不影响故事提示调用。
- `dispose()` 清理循环、一次性 voice、节点和上下文。

### 浏览器流程测试

- 在真实 canvas 或声音按钮手势后，`musicState` 进入 `playing`。
- 所有音乐文件请求成功，未发生重复下载或控制台错误。
- 进入 `chase` 与 `threaten` 时危险混音增强但音乐时间位置不重置。
- 进入 `recover` 后危险层按约 4 秒退出。
- 点击静音、切后台、返回前台并取消静音后能够恢复当前混音。
- 在 390×844 下声音按钮可见、可点击且 ARIA 状态正确。
- 音乐资源故意失败时完整故事路线仍可完成。

### 人工试听

使用耳机和普通扬声器检查：

- 首次操作后的启动延迟与淡入。
- 48 秒循环边界是否可听。
- 探索层是否长期耐听且不掩盖提示音。
- 追逐、近身与脱险变化是否清晰但不突兀。
- reveal 与 escape stinger 是否只播放一次。
- 快速静音、锁屏或切后台返回后的恢复。
- iPhone Safari 与 Android Chrome 的首次解锁、循环与按钮行为。

## 验收标准

1. 游戏首次可信用户操作后启动真实本地背景音乐。
2. 探索与危险循环始终保持同一相位，状态变化不重启音乐。
3. `safe / chase / threaten / recover / complete` 具有可区分且平滑的混音。
4. reveal 与 escape stinger 各自只在对应故事事件播放一次。
5. 静音、持久化、后台恢复和取消静音无持续无声或重复播放路径。
6. 音乐失败时，游戏、任务、危险视觉和完整逃生路线继续可用。
7. 运行时组合真峰值不超过 `-1 dBTP`，发布音频不超过 4 MB。
8. 两个 48 秒循环样本数一致且没有可听接缝。
9. 桌面与 390×844 浏览器测试通过，控制台无音频相关运行错误。
10. 自动化测试、生产构建和人工耳机试听全部完成后才可交付。

## 后续顺序

背景音乐基础完成后，当前游戏质量提升建议按以下顺序继续：

1. 攻击、失败与重试闭环。
2. 视线、听觉与绕障追逐 AI。
3. 手电光束、居民反应和南门状态变化。
4. 主角与标志性变异体的 rigged 模型及动作状态。
5. 地表、植被、田野、树线和远景层。
6. 真实移动端触控。
