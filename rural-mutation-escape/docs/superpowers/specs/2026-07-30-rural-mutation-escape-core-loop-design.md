# 《雾村：逃离》核心逃生闭环设计

日期：2026-07-30
状态：已确认方向，待书面规格复核

## 1. 目标

把当前“能够按顺序走完四个目标的序章原型”升级为一段 2–4 分钟、无需战斗但具备真实压力的逃生竖切：

1. 玩家先发现异常，再亲眼看到熟悉村民变异。
2. 敌人依据视线、声音和短期记忆追逐，而不是只按距离隔墙锁定。
3. 敌人能够抓住玩家并造成失败，玩家可以从稳定检查点快速重试。
4. 南门必须经过真实交互、开启动画和动态碰撞后才能通过。
5. 玩家实际穿过门外结算线后才完成章节，完成后游戏模拟停止。

本轮的判断标准不是“功能更多”，而是让“发现异常 → 躲避追逐 → 开门承压 → 逃出或失败 → 快速重试”形成完整、可重复的游戏闭环。

## 2. 已选方案与取舍

### 已选：玩法优先的非战斗逃生闭环

保留现有地图、第三/第一人称切换、目标顺序、碰撞、动态音乐和程序化视觉资产，集中补齐失败、重试、敌人感知、剧情激活和南门状态。

这是当前收益最高的方案：它能直接解决“没有游戏感”，同时避免在玩法尚未成立时投入大量角色资产和场景美术。

### 暂缓：视觉优先

正式角色、材质、植被、远景、接触阴影和镜头精修仍然重要，但单独完成这些内容只会得到更漂亮的场景演示，不能解决敌人没有结果、南门自动完成的问题。

### 暂缓：移动端优先

触摸摇杆、安全区和横竖屏操作将在核心闭环稳定后单独设计。当前窄屏只作为响应式展示，不宣称移动端可玩。

### 明确不选：战斗优先

本轮不增加武器、攻击、血量、背包、掉落或复杂敌人类型。玩家的主要决策是观察、绕开视线、冲刺脱离、选择开门时机和重试。

## 3. 范围

### 本轮包含

- 游戏生命周期：游玩、揭示演出、被抓、失败、完成。
- 三个会话内检查点和确定性恢复。
- 变异揭示事件及敌人剧情激活。
- 基于视线、声音、记忆和路线图的单敌人追逐。
- 攻击前摇、捕获、失败反馈和快速重试。
- 南门锁定、操作、开启、动态碰撞、最终追逐和门外结算。
- 可走路线航点指引。
- 静态居民和关键大型道具的角色阻挡。
- 对上述流程的单元测试与真实浏览器输入验收。
- 复用现有动态音乐状态，并新增流程事件，不新增音乐资产。

### 本轮不包含

- 正式 rigged GLB 角色和大规模环境换模。
- 战斗、武器、生命值、背包、道具栏或多敌人。
- 浏览器刷新后的剧情存档。
- 触摸移动、移动端实机玩法验收。
- 完整音频重编曲；频谱和响度调整作为后续独立工作。
- 开放世界、分支剧情或第二章。

## 4. 玩家体验流程

### 阶段 A：主角家与收音机

- 玩家出生在主角家院落，敌人逻辑尚未激活。
- 收音机必须有可见实体和持续杂音；互动后广播叫出一个熟悉名字。
- 完成收音机互动后进入“寻找邻居”；在到达下一个稳定检查点前，失败仍恢复到 `home_start`。

### 阶段 B：邻居警告

- 邻居在玩家进入互动范围时看向玩家；互动后通过简短动作指向粮仓方向。
- 完成互动后保存 `courtyard_warning` 检查点：
  - 目标为 `reach_granary`；
  - 收音机和邻居事件已完成；
  - 变异揭示尚未发生；
  - 玩家恢复位置位于院落出口的安全空地。

### 阶段 C：主路变异揭示

- 玩家在 `reach_granary` 阶段首次进入 `sighting` 区域时触发一次揭示。
- 同一个语义角色先显示为普通村民轮廓，再切换为变异姿态；普通和变异视觉绝不能同时显示，也只使用一个碰撞身份。
- 演出最长 1.6 秒：
  - 暂停玩家移动；
  - 相机轻微转向目标；
  - 播放已有揭示音乐事件；
  - 允许 `E`、`Space` 或 `Escape` 跳过；
  - 减少动态效果模式下不移动镜头，只使用字幕、音频和姿态变化。
- 演出结束后给予玩家 0.8 秒反应窗口，再让敌人进入 `investigate`。
- 揭示事件必须幂等；失败重试到 `courtyard_warning` 后允许重新演出一次。

### 阶段 D：前往粮仓并取得手电

- 玩家可通过建筑遮挡和冲刺甩开敌人。
- 手电互动后：
  - 世界中的手电实体隐藏；
  - 玩家获得实际可见的手电光束；
  - 目标切换为 `escape_south_gate`；
  - 南门由 `locked` 切换为 `ready`；
  - 保存 `granary_ready` 检查点。
- 从 `granary_ready` 恢复时，敌人重置到主路的安全搜索位置，不得在玩家身边恢复。

### 阶段 E：开启南门

- 南门初始关闭，并存在明确的角色碰撞体。
- 没有手电时靠近南门只显示“雾太重，看不清门闩”，不能启动开门。
- 门处于 `ready` 时，玩家在正确朝向和距离内按住 `E` 1.8 秒操作门闩：
  - 释放按键、离开范围或被迫移动会取消，进度在 0.4 秒内回落；
  - 操作开始立即发出一次世界噪声事件，强制敌人进入最终追逐；
  - UI 显示可访问的进度反馈；
  - 玩家操作期间不能移动，但可以主动松开 `E` 取消并逃跑。
- 操作完成后进入 `opening`，门扇在 1.2 秒内打开。
- 动态门碰撞必须随可通过缝隙变化；缝隙不足角色直径前仍阻挡玩家与敌人。

### 阶段 F：穿门与章节完成

- 只有当门处于 `open`，且玩家从村内一侧穿过门洞并越过 `z = -38` 的单向结算线时，才能完成章节。
- 结算还要求玩家横向位置处于实际门洞范围，不能绕到围墙外触发。
- 结算后：
  - 玩家、敌人、故事触发和危险更新停止；
  - 门在 1 秒内于玩家身后关闭；
  - 播放现有逃生音乐事件；
  - 显示常驻章节结果层，提供“重新游玩”按钮和键盘操作；
  - 不再显示旧目标、危险提示或互动提示。

## 5. 游戏生命周期

新增独立的游戏流程状态，不再用任务目标隐式代替整个运行状态。

```text
playing
  → reveal
  → playing
  → capturing
  → failed
  → restoring
  → playing

playing
  → completed
```

### 状态规则

- `playing`：玩家、敌人、故事、引导和交互正常更新。
- `reveal`：敌人剧情演出更新；玩家移动被冻结；允许跳过。
- `capturing`：冻结玩家输入，播放最长 0.8 秒捕获反馈。
- `failed`：停止游戏模拟，保留场景画面，显示失败层。
- `restoring`：原子恢复检查点；恢复完成前不运行任何一帧敌人或故事逻辑。
- `completed`：停止游戏模拟，保留结局动画和结果层。

`main.js` 只负责驱动状态机和各子系统，不直接散落失败、恢复或完成条件。

## 6. 检查点设计

检查点只在稳定剧情边界保存，不保存瞬时攻击、交互进度或音频节点。

```js
{
  id,
  objectiveId,
  storyFlags,
  player: { x, z, yaw },
  pursuer: { activated, x, z, yaw, stableState },
  gateState,
  flashlightCollected,
  mutationRevealed
}
```

### 三个检查点

1. `home_start`
   - 初始目标；
   - 敌人未激活；
   - 门为 `locked`；
   - 未获得手电。
2. `courtyard_warning`
   - 邻居事件已完成；
   - 目标为粮仓；
   - 揭示事件尚未发生；
   - 敌人未激活。
3. `granary_ready`
   - 手电已获得；
   - 目标为南门；
   - 揭示已发生；
   - 门为 `ready`；
   - 敌人在预设搜索位置恢复。

### 恢复规则

- 恢复前停止当前捕获、交互进度、临时声音和敌人瞬态计时器。
- 先恢复静态世界状态，再恢复角色位置，最后恢复 UI、引导和音乐模式。
- 无效或不完整的检查点一律回退到 `home_start`，不得留下半开的门或重复角色。
- 连续重试十次不得增加监听器、动画循环、音频循环或角色实例。

## 7. 敌人行为

### 状态

```text
inactive
  → reveal
  → investigate
  → patrol
  → chase
  → windup
  → capture

chase
  → search
  → patrol

windup
  → chase  // 玩家成功拉开距离
```

### 初始参数

| 参数 | 初始值 |
| --- | ---: |
| 巡逻速度 | 1.2 m/s |
| 调查速度 | 2.0 m/s |
| 追逐速度 | 4.4 m/s |
| 南门最终追逐速度 | 4.8 m/s |
| 玩家步行速度 | 保持 3.6 m/s |
| 玩家冲刺速度 | 保持 6.2 m/s |
| 巡逻视距 | 12 m |
| 最终追逐视距 | 16 m |
| 水平视野 | 100° |
| 冲刺声音半径 | 7 m |
| 普通移动声音半径 | 3 m |
| 失去目标记忆 | 2.5 s |
| 捕获前摇 | 0.65 s |
| 前摇触发距离 | 2.25 m |
| 捕获判定距离 | 2.35 m |
| 躲开前摇安全距离 | 2.65 m |
| 前摇失败恢复 | 0.6 s |

这些数值是首轮可测试基线，不是最终平衡值；调参必须保持“敌人快于步行、慢于冲刺”。

### 感知

- 视觉检测同时满足距离、水平视野和二维遮挡检查。
- 遮挡使用与玩法一致的简化碰撞数据，不依赖装饰网格。
- 房屋、实心围墙和关闭的南门阻挡视线；细杆、庄稼和小型装饰不阻挡视线。
- 玩家移动产生声音事件；声音不穿越整个地图，只在半径内把敌人引向最后已知位置。
- 失去视线后，敌人前往最后已知位置并搜索 3 秒，再返回巡逻。
- 路径失败时进入搜索或返回最近合法导航点，绝不能继续推入墙体。

### 路线

- 在 `level-data.js` 中增加稳定 ID 的平面导航图和边。
- 敌人仅在视线完全畅通时直接追向玩家；其他情况通过导航图选择下一节点。
- 导航图与角色碰撞共享验证，所有节点和边必须保持在游戏平面并具有足够净空。

## 8. 引导与互动

### 可走路线指引

为每个目标定义路线航点，而不是始终指向最终锚点的直线。

- 罗盘指向当前尚未到达的下一航点。
- 玩家进入航点半径后推进到下一个航点。
- 最后一个航点完成后才直接指向交互物。
- 检查点恢复时按玩家所在区域重算路线，不保留错误的旧航点索引。
- 屏幕符号使用非对称箭头，旋转后必须表达实际方向。

### 互动约束

- 普通互动同时检查距离、宽松朝向和遮挡。
- 居民、收音机、手电和南门具有稳定互动 ID。
- 静态居民、围栏、水井和储物堆加入数据驱动的角色阻挡；庄稼明确为可穿行装饰。
- 所有互动事件幂等，按键重复或浏览器重复派发不会重复完成剧情。

## 9. UI、反馈与可访问性

### 失败层

- 标题：“你被抓住了”。
- 显示恢复检查点名称。
- 提供可聚焦的“重新尝试”按钮。
- 支持 `R`、`Enter` 和按钮点击。
- 使用 `aria-live` 宣布失败，但不重复播报危险状态。

### 南门进度

- 显示“按住 E 开启铁门”和进度条。
- 进度条提供 `role="progressbar"`、最小值、最大值和当前值。
- 取消操作后视觉与语义进度同步回落。

### 完成层

- 常驻显示章节完成、简短结局文本和“重新游玩”。
- 进入完成层后隐藏任务、罗盘、危险、教程和互动提示。
- 结果层必须可以只使用键盘完成操作。

### 减少动态效果

- 关闭揭示镜头转向、捕获抖动、目标环脉冲和非必要镜头修饰。
- 保留文本、音频、颜色和姿态变化，确保玩法信息不依赖动画。

## 10. 音频事件

继续复用现有音频上下文、总线、动态音乐循环和静音持久化。

新增或明确以下语义事件：

- `mutation-revealed`
- `pursuer-detected-player`
- `pursuer-lost-player`
- `gate-operation-started`
- `gate-opened`
- `player-captured`
- `checkpoint-restored`
- `chapter-completed`

本轮不新增或重编音乐文件。事件无法播放音频时，视觉、剧情和失败流程仍必须正常完成。音频频谱和整体响度重做将在核心闭环稳定后单独验收。

## 11. 模块边界

### 新增模块

- `game-flow.js`
  - 只管理生命周期状态和允许的转换；
  - 不直接读写 Three.js 对象。
- `checkpoints.js`
  - 创建、验证和恢复稳定快照；
  - 不持有音频节点或 DOM 引用。
- `south-gate.js`
  - 管理门状态、交互进度、门扇动画和动态碰撞；
  - 通过事件通知故事和音频。
- `perception.js`
  - 提供视野、遮挡和声音半径的纯计算函数。

### 修改模块

- `pursuer.js`
  - 消费感知结果和导航图；
  - 输出稳定 AI 状态与捕获事件。
- `story.js`
  - 管理剧情目标与幂等世界事件；
  - 不直接负责失败或检查点恢复。
- `level-data.js`
  - 增加导航图、路线航点、门碰撞、结算线和静态 NPC/道具碰撞。
- `guidance.js`
  - 从目标直线升级为路线航点。
- `ui.js`
  - 渲染失败、南门进度和完成层。
- `main.js`
  - 组合模块、分派每帧更新并统一销毁；
  - 不保留独立的临时 `restart()` 逻辑。

## 12. 异常处理

- 状态机拒绝非法转换，并在开发模式给出一次性诊断。
- 无法求得导航路径时，敌人回到最近合法节点，不能穿墙追逐。
- 缺少目标航点时停止显示错误指引并保留任务文本，不能崩溃。
- 门动画或动态碰撞恢复失败时回退到检查点声明的完整门状态。
- 音频加载失败不阻断剧情、失败、重试或完成。
- WebGL 页面离开、恢复和热更新必须统一停止旧的 RAF、监听器、角色、材质和音频所有者。

## 13. 验证策略

### 单元测试

- 生命周期所有合法和非法转换。
- 三个检查点的创建、验证、恢复和无效快照回退。
- 揭示事件只触发一次，检查点恢复后按设计重新触发。
- 视野角度、距离、建筑遮挡、声音半径和目标记忆。
- 敌人速度关系、前摇逃脱、捕获和搜索恢复。
- 南门状态、按住进度、取消回落、动态碰撞和单向结算线。
- 路线航点推进、恢复重算和缺失航点降级。
- 居民及关键大型道具碰撞。
- 完成后玩家、敌人和故事不再更新。

### 浏览器验收

- 使用真实键盘事件完成关键路线段，不以逐目标传送代替完整可走性证明。
- 验证建筑绕行、灯杆滑动、居民阻挡和门关闭/开启。
- 验证敌人不能隔建筑发现玩家。
- 验证玩家原地等待会被抓，冲刺并绕开视线可以脱离。
- 分别从 `courtyard_warning` 和 `granary_ready` 失败并重试。
- 验证未开门、门前区域和绕墙均不能完成章节。
- 验证实际穿门后停止模拟并显示结果层。
- 连续重试十次，确认没有重复 RAF、监听器、音频循环或角色实例。
- 在 1280×720 和 390×844 检查 UI；390×844 只验证显示，不宣称触摸可玩。

### 回归

- 现有碰撞、相机、鼠标转向、第一/第三人称、任务顺序、动态音乐、静音持久化、缺失音频降级和无障碍声音按钮测试继续通过。
- 核心闭环改动不得增加超过基线 10% 的代表场景 draw call；若超过，必须先定位新增对象来源。

## 14. 验收标准

1. 第一次正常游玩可在 2–4 分钟内完成，不依赖调试传送。
2. 敌人只在剧情揭示后激活，不能隔房屋无条件发现玩家。
3. 敌人在开放道路上能追上步行玩家，但玩家冲刺和绕视线能够脱离。
4. 近身前摇可读；玩家不躲避会被捕获并进入失败层。
5. 重试恢复到正确检查点，世界、门、手电、故事、敌人和音乐状态一致。
6. 南门必须实际操作并打开，玩家真正穿过门洞和结算线后才完成。
7. 完成后停止游戏模拟，结果层保持可读、可聚焦、可重新游玩。
8. 玩家、敌人、居民、建筑、路障和路灯碰撞不重合、不穿透。
9. 自动化测试、生产构建和一轮真实桌面浏览器完整游玩全部通过。

## 15. 后续顺序

本设计完成后，后续工作按以下顺序独立设计与实施：

1. 音乐频谱、响度和空间化环境音重做。
2. 主角、居民和变异体的正式模型与状态动画。
3. 农村环境资产、材质、接触阴影和镜头精修。
4. 触摸控制、移动质量档和真机验收。
