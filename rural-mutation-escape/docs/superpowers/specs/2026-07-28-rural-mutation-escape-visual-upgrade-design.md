# 《雾村：逃离》视觉升级设计规格

## 目标

将当前可运行的白盒原型升级为具有明确中式乡村民俗恐怖气质的第三人称序章。优化重点是第一眼构图、路线可读性、环境叙事和角色可信度；保留现有故事状态、控制方式与单平面玩法，不在本轮引入复杂战斗、联网或开放世界。

## 当前基线与问题

浏览器基线显示，初始相机进入或贴近地面，深色地面遮挡了大部分视野，玩家无法建立主角、道路与目的地之间的空间关系。建筑由少量大体块组成，缺少农村场景的尺度参照和前景、中景、远景层次；角色轮廓较弱，标题卡占据过多注意力。

本轮必须先解决以下问题：

1. 初始镜头与跟随镜头不得穿入地面、墙体或屋顶。
2. 玩家出生后应同时看见主角、院门、主路方向和一个远处异常线索。
3. 五个故事区域必须依靠不同轮廓、灯光和道具被识别，而不是依靠调试标记。
4. 角色需要具有清晰的人体比例、服装轮廓和可读姿态。
5. 界面必须服务叙事和操作，不得持续遮挡主要游戏空间。

## 视觉方向

采用“中式乡村民俗恐怖 + 风格化低多边形”的混合方向。

- 造型：简化几何与手工感边缘，避免写实资产与占位几何混搭。
- 色彩：冷青灰暮色作为环境基调，灯笼、窗灯和手电使用低饱和暖色；危险状态加入暗红提示，但不大面积染红画面。
- 材质：泥墙、旧木、瓦片、湿土和枯草使用不同粗糙度与色差，不依赖高分辨率贴图。
- 氛围：低层薄雾、屋内微光、远处炊烟和轻微暗角建立压迫感；所有局部光必须对应可见光源。
- 构图：主路形成主要视线轴，院墙和作物形成侧向框景，祠堂或村口剪影提供远景锚点。

## 关卡构图

全部可玩内容继续位于同一水平地面。屋顶、树冠和远景山体只作为不可通行背景，不参与移动、碰撞或导航。

### 主角家与院落

主角出生在老宅院内。镜头位于右后方，院门偏向画面中央，收音机和窗灯位于近景一侧。院墙、木门、柴堆、水缸和晾晒物建立生活痕迹。院门是第一条明确通路。

### 村中主路

主路采用不规则土路边界，不使用贯穿地图的矩形色块。路边加入排水沟、低矮土墙、木栅栏、菜地、玉米秆、电线杆和散落农具。路灯数量有限，用暖光形成连续但不完全安全的路径。

### 祠堂与异常目击区

祠堂使用更高的屋脊、封闭大门和暗红残灯形成危险地标。变异事件发生在主路转折处，玩家能从遮挡物之间先看到异常剪影，再进入完整视野。

### 粮仓

粮仓通过高墙、堆袋、木架和冷色手电光建立搜寻场景。该区域提供短暂遮蔽，但不引入室内多层结构。

### 南门

南门由门楼轮廓、倾倒路障、废弃三轮车和远处雾中道路构成。它始终在主路远端提供方向感，但只有完成既有故事条件后才进入完成状态。

## 建筑与环境模块

建筑仍使用程序化 Three.js 几何，但拆分为可组合模块：

- 墙体、墙基、木梁、窗框、门、屋檐和双坡瓦屋顶；
- 院墙、门柱、栅栏、路边沟和道路边缘；
- 水井、柴堆、水缸、箩筐、麻袋、木架和废弃农具；
- 树干与分层树冠、枯草簇、菜畦和玉米秆；
- 电线杆、灯笼、窗灯和炊烟。

每栋主要建筑至少拥有一个独特轮廓特征和一个环境叙事道具。重复模块通过尺寸、旋转、色差和道具组合产生变化。

## 相机

第三人称为默认模式，目标构图是主角位于画面下方约三分之一处，前进方向保持足够视野。

- 初始化时直接设置到合法位置，避免从世界原点插值穿过地面。
- 目标点跟随主角胸口至肩部高度；相机距离、俯仰和视野角保持稳定。
- 相机最低高度受到地面约束。
- 主角与相机之间执行简化射线遮挡检查；命中建筑时相机沿视线拉近，离开遮挡后平滑恢复。
- 第一人称切换共享偏航和俯仰，不改变玩家位置、故事状态或交互距离。
- 开场只使用一个短暂、可跳过的构图稳定过程，不制作独立过场动画系统。

## 角色

本轮继续使用原创程序化角色，不引入来源不明或风格不统一的外部模型。

- 主角：头、颈、躯干、上臂、前臂、手、腿和脚分段，使用外套、裤子、鞋和头发形成明确轮廓。
- 居民：复用统一骨架式层级，通过服装色、体型和姿势区分；躲藏居民采用弯腰、侧身和回望姿态。
- 变异者：保留人体基础但加入不对称肩线、前倾躯干、异常手臂长度和冷色皮肤，避免仅靠颜色区分。
- 移动：主角与追逐者使用程序化摆臂、摆腿和身体起伏；静止时保持轻微呼吸。

角色模块只暴露位置、朝向、移动状态和姿态状态，故事与追逐逻辑不得依赖具体网格节点。

## 灯光、雾与后期感

- 一个低强度半球光提供冷色环境照明。
- 一个暖色低角度方向光模拟暮色，并提供长阴影。
- 灯笼、窗灯和手电的点光或聚光必须与可见发光网格共存。
- 雾距离确保玩家能看见下一地标，同时隐藏地图边界。
- 使用 CSS 暗角与轻微噪点增加电影感；不引入高成本后处理框架。
- 阴影只分配给主角、主要建筑、追逐者和靠近路线的关键道具，远景装饰不投射阴影。

## 界面与故事引导

标题卡在开场短暂显示后缩小或淡出，常驻界面只保留：

- 左上角简洁章节与目标；
- 下方居中的临时对白字幕；
- 靠近可交互对象时出现的 `E` 提示；
- 右下角低干扰控制提示，并在首次操作后降低不透明度。

调试用彩色柱形标记从正式画面中移除。目标方向依靠道路、灯光和地标表达；必要时使用短暂、低亮度的世界空间光圈，不使用持续悬浮箭头。

## 行为边界

本轮保留现有故事顺序、视角切换、居民、追逐者与南门完成条件。视觉升级可以修复为了画面与路线所需的相机、碰撞和交互距离问题，但不新增攻击、武器、物品栏或复杂敌人类型。

所有新装饰必须与碰撞层分离。只有房屋主体、院墙、栅栏、路障和地图边界进入简化碰撞；小型道具不得卡住玩家或追逐者。

## 性能与适配

- 桌面浏览器以 1280×720 和 1440×900 为主要验证视口。
- 高重复道具优先共享几何与材质；草、作物和远景树可使用实例化网格。
- 像素比设置上限，阴影贴图与动态灯数量保持受控。
- 不要求独立显卡；集成显卡或软件 WebGL 环境仍应能够进入场景和完成路线。

## 验收标准

1. 进入页面后两秒内，画面中可同时识别主角、院门、主路方向和远处地标。
2. 第三人称相机在出生、移动、旋转和建筑附近均不穿地、不穿墙，第一人称切换后状态连续。
3. 主角家、主路、祠堂、粮仓和南门具有不同的轮廓、道具与灯光特征。
4. 主角、躲藏居民和变异者在正常游戏距离下可通过轮廓与姿态区分。
5. 标题卡会退出主要视野，目标、字幕和交互提示在 1280×720 下不互相遮挡。
6. 从主角家到南门的现有故事路线仍可完成；关键交互需要在对象附近触发。
7. 浏览器控制台无运行错误，自动化冒烟测试、构建以及一轮实际浏览器试玩验证通过。
8. 最终保留出生画面、主路异常画面和南门画面三张浏览器证据截图。

## 实施顺序

1. 修复相机初始化和地面遮挡，建立稳定第三人称构图。
2. 重构道路、建筑和五区地标，建立前中远景层次。
3. 增加农村环境模块、光照、雾和界面收敛。
4. 重构程序化人物并加入基础姿态动画。
5. 修复相邻的碰撞与近距离交互问题。
6. 完成自动化、构建与浏览器三状态验证。
