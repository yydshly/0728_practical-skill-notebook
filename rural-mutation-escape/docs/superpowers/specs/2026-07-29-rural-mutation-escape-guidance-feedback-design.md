# 《雾村：逃离》引导与游戏反馈设计

## 目标

将当前“可行走、可按顺序触发剧情”的场景原型升级为具有明确行动闭环的序章体验。玩家应始终知道下一步要做什么、目标位于哪个方向、距离目标还有多远、刚刚完成了什么，以及追击危险是否正在升级。

本轮采用“混合引导”方向：远距离由简洁的任务卡、罗盘和距离提示负责方向判断；接近目标后，由世界空间标记和交互提示负责最后定位；任务完成和追逐状态通过视觉与音频共同反馈。

## 范围

- 保留现有第三人称探索、第一人称观察、四阶段故事顺序和单平面村庄地图。
- 增加任务阶段、目标方向与距离、屏幕边缘指示、世界目标标记、分级交互提示和渐进式操作教学。
- 增加任务完成、开始追逐、近身威胁和脱离危险的视觉与音频反馈。
- 增加静音控制、减少动态效果适配和音频失败降级。
- 扩展自动化测试与真实浏览器验证场景。

## 非范围

- 不增加战斗、武器、生命值、物品栏、存档、联网或多种敌人。
- 不增加地面导航线、持续发光路径或小地图。
- 不改变地图的单平面移动规则，不增加楼梯、跳跃或垂直路线。
- 不依赖外部版权音频或新的外部模型素材。
- 不把视觉标记、装饰几何或音频状态用于碰撞、导航和故事判定。

## 玩家体验闭环

故事流程保持为四个连续阶段：

1. `调查收音机 1/4`
2. `找到邻居 2/4`
3. `获取手电 3/4`
4. `逃往南门 4/4`

每个阶段执行同一套可预期的反馈循环：

1. 任务卡给出动作和一句剧情线索。
2. 罗盘给出目标方向和直线距离。
3. 目标进入 12 米范围后，场景中显示低亮度脉冲光圈。
4. 进入预接近范围后提示“靠近并调查”；进入实际交互范围后切换为 `[E]` 操作。
5. 完成目标时，任务卡短暂显示勾选，播放轻量提示音并显示结果字幕。
6. 完成反馈结束后切换至下一阶段，罗盘、距离和世界标记同步更新。

## 界面布局

### 任务卡

任务卡位于左上角，显示阶段编号、主要动作和剧情线索。任务完成后保持约 0.8 秒的勾选状态，再过渡至下一阶段。

任务卡必须保持简洁，不展示完整任务列表，不覆盖玩家、道路中心或主要地标。

### 目标罗盘

罗盘位于画面顶部中央，只显示当前任务目标：

- 目标在视野内时显示菱形标记和距离。
- 目标离开视野时，标记被限制在安全屏幕边缘，并显示指向目标的方向。
- 距离按整数米显示，进入 3 米内后改为“就在附近”。
- 已完成章节不显示目标罗盘。

### 世界目标标记

世界标记使用程序化 Three.js 几何，绑定当前任务的稳定目标锚点：

- 12 米外隐藏，避免全地图持续发光。
- 12 米内显示低矮光圈和轻微垂直脉冲。
- 进入交互范围后降低脉冲强度，避免与交互提示争夺注意力。
- 标记不参与碰撞、导航、光照判定或故事触发。

### 交互提示

交互提示分为两级：

- 目标进入预接近范围但尚不可操作时，显示“靠近：目标名称”。
- 进入现有有效交互距离后，显示 `[E] 操作名称`。

提示在目标离开范围、目标完成或故事阶段变化后立即隐藏。

### 渐进式教学

教学提示只在首次相关行为前出现，并在行为完成后永久淡出：

- 首次移动：`WASD 移动`
- 首次奔跑：`Shift 奔跑`
- 首次可交互：`E 互动`
- 首次镜头操作：`鼠标环顾`
- 首次视角切换前：`C 切换视角`

本轮不做跨刷新持久化；刷新页面后教学状态重置。

## 追逐反馈

追逐反馈直接读取追击者公开状态和玩家距离，不依赖角色网格节点。

### 状态

- `安全`：追击者处于巡逻或失去目标状态，不显示危险反馈。
- `已被发现`：追击者进入追逐状态，显示低强度暗红边缘和危险标签。
- `近身威胁`：追击者进入 `threaten` 状态，边缘脉冲和心跳频率提高。
- `脱离危险`：追击结束后，视觉与音频在约 1.2 秒内平滑淡出。

追逐反馈不得替换当前故事目标。逃往南门阶段仍保留南门方向，危险标签作为独立状态出现。

### 视觉

- 使用透明暗红边缘脉冲，不使用大面积纯红覆盖。
- 不持续晃动镜头；本轮只在追逐状态变化时使用短促的界面反馈。
- `prefers-reduced-motion: reduce` 下取消强脉冲与位移动画，只保留颜色和文字状态。

### 音频

音频使用 Web Audio API 实时生成，不引入外部素材：

- 首次用户键盘或鼠标操作后解锁音频。
- 任务完成播放短促双音提示。
- 开始追逐播放低频警告音。
- 近身威胁播放随距离变化的心跳。
- 脱离危险后心跳平滑淡出，不重新启动完整音轨。

右下角提供静音按钮。音频上下文不可用、被浏览器阻止或恢复失败时，视觉反馈继续正常工作，不阻塞游戏。

## 数据和系统边界

### 目标定义

建立统一、可验证的目标定义，至少包含：

- 稳定目标 ID
- 阶段编号与总阶段数
- 故事状态 ID
- 目标锚点 ID
- 显示标题和剧情线索
- 交互类型与操作文案
- 是否允许世界标记和距离提示

南门阶段使用现有 `south_gate` 锚点和 `south_gate_exit` 完成区域。其他阶段分别使用 `radio`、`neighbour` 和 `flashlight` 锚点。

### 引导系统

引导系统输入当前目标、玩家位置和相机状态，输出只读引导快照：

- 当前阶段和文案
- 目标世界坐标
- 距离和方向角
- 是否进入世界标记范围
- 是否进入预接近或交互范围
- 目标投影后的屏幕位置与边缘状态

引导系统不直接修改故事、玩家、相机或追击者状态。

### 故事事件

故事系统在阶段变化时产生一次性事件：

- `objective-completed`
- `objective-started`
- `chapter-completed`

反馈系统消费事件并触发任务卡过渡、字幕和音效。重复调用渲染不得重复产生奖励或声音。

### 危险系统

危险系统输入追击者状态和玩家距离，输出安全、追逐、近身和恢复状态。它只驱动界面与音频，不改变追击逻辑。

### 界面系统

界面系统负责：

- 任务卡
- 罗盘和屏幕边缘标记
- 分级交互提示
- 教学提示
- 完成反馈
- 危险状态
- 静音按钮

世界标记由独立 Three.js 场景模块维护，避免把 3D 对象逻辑混入 DOM 界面。

## 数据流

每帧按以下顺序更新：

1. 更新玩家移动和相机。
2. 更新当前交互候选和追击者。
3. 更新故事完成条件并产生阶段事件。
4. 根据最新故事、玩家和相机状态计算引导快照。
5. 根据追击者状态和距离计算危险快照。
6. 更新 DOM 界面、世界目标标记和音频参数。
7. 渲染场景。

交互事件按以下顺序处理：

1. 校验当前故事阶段允许的交互类型。
2. 完成当前目标并产生一次性完成事件。
3. 播放完成反馈。
4. 启动下一目标并更新所有引导层。

## 降级与错误处理

- 目标定义引用不存在的锚点时，隐藏罗盘和世界标记，保留文字任务，并在开发环境给出明确错误。
- 相机投影结果无效时，不显示屏幕标记，不影响移动和故事。
- 音频创建、解锁、暂停恢复或节点生成失败时自动静音，视觉反馈保持可用。
- 静音状态只影响声音，不影响字幕、危险标签和任务完成提示。
- 页面切到后台时暂停或降低音频；返回前台后按当前危险状态恢复，不叠加旧声音。

## 验证

### 单元测试

- 每个故事阶段映射到正确锚点、标题、阶段编号和交互类型。
- 方向角、距离、屏幕边缘限制和近距离文案计算正确。
- 预接近范围与实际交互范围互不混淆。
- 故事阶段每次只产生一次完成事件和一次开始事件。
- 追逐、近身、恢复和安全状态转换正确。
- 缺少锚点或无效投影时安全降级。
- 静音和音频不可用状态不影响视觉事件。

### 浏览器流程测试

- 完整执行收音机、邻居、手电和南门路线，确认阶段按 `1/4` 至 `4/4` 推进。
- 转动镜头和背对目标，确认罗盘标记方向与屏幕边缘位置正确。
- 从远距离接近目标，确认世界标记、预接近提示和 `[E]` 提示按顺序出现。
- 触发追逐、近身威胁和脱离危险，确认视觉状态、危险文案和音频状态同步。
- 验证静音、首次音频解锁、切换后台返回和减少动态效果。
- 在 1280×720 与 1440×900 下确认任务卡、罗盘、字幕、交互提示和控制提示互不遮挡。
- 检查控制台错误、渲染调用、三角形数量和代表性流程中的稳定性。

## 验收标准

1. 开场结束后 3 秒内，玩家能看到第一目标、方向和距离。
2. 目标不在视野内时，罗盘标记能够正确指向并停留在安全屏幕边缘。
3. 目标进入 12 米范围后出现世界标记，进入实际交互距离后出现明确 `[E]` 提示。
4. 四个任务阶段按固定顺序推进，不能跳步、重复完成或重复播放奖励。
5. 每次完成目标都有可见勾选、结果字幕和可静音提示音。
6. 追逐、近身威胁和脱离危险在视觉与音频上可区分，且不遮挡主要游戏空间。
7. 音频未授权、静音或恢复失败时，游戏与视觉引导仍可完整运行。
8. 减少动态效果设置下不出现强脉冲或明显位移动画。
9. 1280×720 与 1440×900 下，常驻和临时界面不互相遮挡。
10. 自动化测试、生产构建和真实浏览器完整路线验证通过，控制台无运行错误。
