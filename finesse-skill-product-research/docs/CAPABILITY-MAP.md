# Finesse 能力地图

## 证据范围与阅读方式

本地图只陈述固定提交 [`ba004b21e14e55385992dff6e345db7108deca78`](https://github.com/mouse-lin/finesse-skill/tree/ba004b21e14e55385992dff6e345db7108deca78) 中可直接追溯的能力事实。主要一手来源为上游 [README.md](https://github.com/mouse-lin/finesse-skill/blob/ba004b21e14e55385992dff6e345db7108deca78/README.md)、[skills/finesse-ui/SKILL.md](https://github.com/mouse-lin/finesse-skill/blob/ba004b21e14e55385992dff6e345db7108deca78/skills/finesse-ui/SKILL.md)、[references/preflight.md](https://github.com/mouse-lin/finesse-skill/blob/ba004b21e14e55385992dff6e345db7108deca78/skills/finesse-ui/references/preflight.md) 与 [scripts/detect.mjs](https://github.com/mouse-lin/finesse-skill/blob/ba004b21e14e55385992dff6e345db7108deca78/skills/finesse-ui/scripts/detect.mjs)。

Finesse 是设计决策与执行指导 Skill，不是浏览器运行时组件库，也不会仅靠安装自动生成产品。以下“输出”表示该 Skill 要求或引导 AI 助手产生的决策、文件或代码行为，并不等同于本研究已进行的运行时验证。

| 能力组 | 用户问题 | 机制 | 输出 | 证据 | 限制 |
|---|---|---|---|---|---|
| **register 路由** | 我的 brief 应走品牌表达、产品信息界面还是电商任务流？ | 在生成前执行 Brand Read，按 `brand`、`product`、`commerce` 识别页面任务；产品再区分“读数据”的 dashboard 与“完成有后果操作”的 workflow。 | 一行 Design Read，以及对应的参考资料和设计语法选择。 | [SKILL.md §0](https://github.com/mouse-lin/finesse-skill/blob/ba004b21e14e55385992dff6e345db7108deca78/skills/finesse-ui/SKILL.md#0-brand-read-before-anything)；[README 的工作步骤](https://github.com/mouse-lin/finesse-skill/blob/ba004b21e14e55385992dff6e345db7108deca78/README.md#它怎么工作)。 | register 是对 brief 的推断，复杂或含混的 brief 仍可能需要用户确认；它不替代真实需求、信息架构或用户研究。 |
| **SOUL / SPECTACLE / DENSITY** | 页面应有多强的个性、技术视觉表现与信息密度？ | 把 SOUL、SPECTACLE、DENSITY 显式设为 1–10 的三旋钮，并从 Design Read 推导；产品 register 通常压低 SPECTACLE、提高 DENSITY。 | 记录的旋钮值、视觉引擎选择和信息密度方向。 | [SKILL.md §1](https://github.com/mouse-lin/finesse-skill/blob/ba004b21e14e55385992dff6e345db7108deca78/skills/finesse-ui/SKILL.md#1-the-three-dials)；[preflight 的 Design Read 与 spectacle 检查](https://github.com/mouse-lin/finesse-skill/blob/ba004b21e14e55385992dff6e345db7108deca78/skills/finesse-ui/references/preflight.md)。 | 高 SPECTACLE 不是装饰承诺：`≥7` 时必须有真实引擎、降级策略与设备性能验证；旋钮本身不保证美感、可用性或帧率。 |
| **brand 路线** | 落地页、品牌站或发布页如何避免落入默认模板？ | 选择 soul/persona、品牌 substrate 与一个 hero engine；可使用 Three.js、Canvas、WebGL FBO、GSAP 或 CSS-only，并要求动效具有理由与降级。 | 有明确人格、配色和字体方向的品牌页面设计，以及一个非承重的视觉引擎。 | [SKILL.md 的 brand 分流与 hero engine](https://github.com/mouse-lin/finesse-skill/blob/ba004b21e14e55385992dff6e345db7108deca78/skills/finesse-ui/SKILL.md#4-the-hero-engine-finesses-differentiator--brand-register)；[README 的核心能力](https://github.com/mouse-lin/finesse-skill/blob/ba004b21e14e55385992dff6e345db7108deca78/README.md#核心能力)。 | 品牌 grammar 不应套用到 dashboard；浏览器、`prefers-reduced-motion`、中端设备性能和真实像素仍需逐页验证。 |
| **product 路线** | 仪表盘、后台、分析页如何优先保障可读性、密度与操作清晰？ | 使用产品 substrate、颜色库、组件系统、数据可视化和信息结构；按“read”页面选择 dashboard 模式，按“operate”页面追加 workflow 参考。 | dashboard、admin、analytics、data table、app shell 或 settings 的设计与实现指引。 | [SKILL.md 的 product 分流](https://github.com/mouse-lin/finesse-skill/blob/ba004b21e14e55385992dff6e345db7108deca78/skills/finesse-ui/SKILL.md#0a-determine-the-register-this-forks-every-later-decision)；[README 的 product UI 路线](https://github.com/mouse-lin/finesse-skill/blob/ba004b21e14e55385992dff6e345db7108deca78/README.md#核心能力)。 | 它不是现成组件集合；色彩、表格、图表、提交后果和可访问性仍需结合真实业务数据与实现环境判断。 |
| **commerce 路线** | 单品 PDP 与多商品 PLP、购物车、结算应如何分别设计？ | 将 commerce 作为混合 register：PDP 倾向 brand（但保留规格、评价和信任信息密度），PLP/marketplace 倾向 product（筛选、排序、网格与低 SPECTACLE），再加载电商专用规则。 | PDP、PLP、cart 与 checkout 的骨架选择及反暗模式提醒。 | [SKILL.md 的 commerce 路由](https://github.com/mouse-lin/finesse-skill/blob/ba004b21e14e55385992dff6e345db7108deca78/skills/finesse-ui/SKILL.md#0a-determine-the-register-this-forks-every-later-decision)；[README 的 commerce-ui 目录说明](https://github.com/mouse-lin/finesse-skill/blob/ba004b21e14e55385992dff6e345db7108deca78/README.md#仓库结构)。 | 路由基于页面任务，不涵盖库存、支付、税务、风控或真实交易后端；反暗模式规则不能代替合规审查。 |
| **命令式迭代** | 已有页面只需解决“太平”“太花”“不对味”等局部问题时，怎样避免整页重做？ | 以 `craft`、`audit`、`bolder`、`quieter`、`soul`、`animate`、`depth`、`densify`、`redesign`、`init`、`document` 等动词路由到单一参考资料或任务。 | 聚焦的设计调整；`audit` 输出只读 findings，其他命令可修改目标。 | [SKILL.md 的 Commands 表](https://github.com/mouse-lin/finesse-skill/blob/ba004b21e14e55385992dff6e345db7108deca78/skills/finesse-ui/SKILL.md#commands)。 | 命令映射是 Skill 指引而非独立 CLI 服务；命令是否被执行、是否正确改动代码，取决于承载它的 AI 助手与用户确认。 |

## 能力边界结论

固定提交展示的是一套可组合的设计决策与执行约束：它能将 brief 组织为 register、三旋钮、参考资料、局部迭代命令、项目记忆和检查流程。上述内容为“上游已定义的机制”；关于其在真实项目中的效果、浏览器表现、性能与可访问性结果，仍应由后续受控实验和浏览器证据确认。
