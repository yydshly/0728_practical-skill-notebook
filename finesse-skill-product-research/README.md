# Finesse Skill 产品研究

## 项目结论

Finesse 是一套面向 AI 编码助手的前端设计决策与执行指导 Skill：它先根据 brief 路由设计语境，再用明确的设计旋钮、参考资料和交付前检查约束生成或改造工作；它提供的是工作流与判断框架，而不是可在浏览器中直接调用的 UI 组件。

## Finesse 是什么 / 不是什么

Finesse 为 Claude Code、Codex 等 AI 编码助手提供设计流程：先完成 Design Read，识别页面的 register，再选择设计方向并按需加载参考资料。它覆盖品牌页面、产品型界面、工作流页面与电商页面的设计决策，并把反廉价规则、可访问性、动效降级与交付前检查纳入流程。

它不是组件库：不提供浏览器运行时 API，也不是安装后自动生成完整产品的生成器。Skill 的规则需要由兼容的 AI 编码助手在具体 brief、代码库与交付环境中解释和执行；其静态检测结果更不能替代真实浏览器渲染、交互、性能或人工审美验证。

## 研究问题

1. 固定提交中已经定义了哪些可追溯的设计决策、执行指引和质量门禁？
2. 这些机制如何把同一个自然语言 brief 路由为不同的前端设计工作流？
3. 哪些结论仍需通过受控实验、浏览器证据和对照输出验证，才适合进一步产品化？

## 四阶段研究路线

1. **能力审计**：固定版本，阅读主 Skill、关键参考资料、示例和静态 detector。
2. **受控实验**：用同一组 brief 分别测试 brand、dashboard、workflow 与 commerce 情境。
3. **对照验证**：比较无 Skill、原版 Finesse 和调整后策略的输出，并保留浏览器与人工评审证据。
4. **产品归纳**：把已验证机制沉淀为能力模型、机会地图和展厅叙事。

## 推荐产品主线

推荐将后续产品化主线定位为“设计决策与审计工作台”：把 brief 路由、Design Read、设计旋钮、设计模型与输出审计串成可检查的闭环。该判断是研究方向，不表示任何产品已经实现或验证。
